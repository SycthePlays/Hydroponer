# 10. Tutorial Generation

The tutorial is what turns a plan into a built system. It is the last stage of the pipeline and the one where a language model does the most visible work — but it works from a skeleton the engine derives, not from imagination.

---

## 10.1 The two-part approach

**The engine derives the structure. The model writes the words.**

The engine produces an ordered graph of build steps directly from the layout: which components exist, what they connect to, what must exist before what. That graph is deterministic and complete — it cannot omit a component, because it is generated by walking the BOM.

The model then writes each step's instruction text, given the step's structured definition. It cannot add a step, remove a step, reorder steps, or reference a part that is not in that step's part list.

This is the difference between a tutorial that is *readable* and a tutorial that is *correct*. The split gets both.

---

## 10.2 Deriving the build graph

Assembly order comes from dependency rules, not from a model's sense of narrative:

| Rule | Example |
|---|---|
| Structure before contents | Bench frames before channels |
| Dry work before wet work | All cutting and drilling before any water |
| Plumbing before electrical | Avoid working near live circuits with water present |
| Test before commit | Leak-test with plain water before adding nutrients or plants |
| Bottom-up by height | Reservoir placed before what sits above it |
| Fixed before adjustable | Mount lighting rails before setting the hanging height |
| Seeds started in parallel | Germination starts on day one, in parallel with the build, because seedlings take 10–14 days |

That last rule matters more than it looks. A tutorial that has the user finish the build and then start seeds wastes two weeks. The engine emits seed-starting as a phase-zero step running concurrently.

The graph is then partitioned into **phases** — coherent sessions of work, each ending at a natural stopping point where the build can be safely left. Users do not build in one sitting.

### Typical phase structure

```
Phase 0  Before you start        Order parts, start seeds, prepare the space
Phase 1  Frame and benches       Assemble structure, level, position
Phase 2  Grow modules            Channels or vessels, net pot holes, end caps
Phase 3  Reservoir and plumbing  Reservoir, pump, tubing, fittings, return
Phase 4  Leak test               Plain water, run 30 minutes, fix leaks
Phase 5  Electrical              RCD/GFCI, timers, drip loops, cable management
Phase 6  Lighting                Mount, set height, set the photoperiod
Phase 7  Commissioning           Fill, mix nutrients, set pH and EC, transplant
```

Phase 4 is a phase of its own, and always is. Finding a leak with plain water on a bare bench is a nuisance; finding it after transplanting into a nutrient-filled system is a flood and a lost crop.

## 10.3 Step definition

Each step is emitted by the engine as a structured record. The model fills only the text fields.

```ts
type TutorialStep = {
  id: string
  phase: number
  index: number

  // Engine-derived — the model may not change these
  parts: BomLineRef[]              // exactly what this step consumes
  tools: ToolRef[]
  depends_on: string[]             // step ids
  measurements: Measurement[]      // e.g. { label: 'channel length', value_mm: 2400 }
  estimated_minutes: number
  difficulty: 1 | 2 | 3
  safety_flags: SafetyFlag[]       // template text is inserted verbatim from these
  verification: string             // engine-templated: how to know the step worked

  // Model-authored
  title: string
  instruction: string              // 2-5 sentences
  tip: string | null               // optional, one sentence
}
```

The `verification` field is engine-templated rather than model-authored because it is the step's correctness criterion — "the channel should fall 60 mm over its 2.4 m length; check with a spirit level" is derived from the layout's slope specification, not composed.

## 10.4 Writing constraints

The narration prompt for tutorials enforces:

- **Only supplied parts.** Every component named must appear in that step's `parts`. Post-validation rejects any other component name found in the text.
- **Only supplied numbers.** Every measurement must come from `measurements`. Numeric-token validation applies as described in [AI Pipeline](06-ai-pipeline.md#post-validation).
- **Imperative, second person, present tense.** "Cut the channel to 2400 mm" — not "the channel should then be cut."
- **One action per sentence.** Compound instructions are where beginners lose their place.
- **Skill-matched detail.** For "assemble only" users, basic technique is explained (how to cut PVC squarely, how to find a stud). For experienced users, it is omitted. The same step definition produces different text for different users; the structure is identical.
- **No hedging.** "You may want to consider possibly checking" is banned by prompt and flagged in review. A tutorial states what to do.
- **Length ceiling.** Five sentences per step. If a step needs more, the engine should have split it — that is a build-graph bug, and the validator reports it as one.

## 10.5 Safety content

Safety text is never generated. Each `SafetyFlag` maps to fixed template text with slotted engine values:

| Flag | Template (values slotted from the engine) |
|---|---|
| `electrical_water_proximity` | "This step puts a powered device near water. Plug it into an RCD/GFCI-protected outlet and form a drip loop in the cable so water runs off before reaching the socket." |
| `structural_load` | "Filled, this component weighs about {mass_kg} kg. It must sit on the floor, not on a shelf or elevated surface, unless you have had the support verified." |
| `chemical_handling` | "Wear gloves and eye protection. Add concentrate to water — never water to concentrate. Mix parts A and B separately into the reservoir; never combine them at full strength." |
| `sharp_tools` | "Cut away from your body and secure the workpiece. A slipping blade on a round pipe is the most common injury in this build." |
| `working_at_height` | "Have someone steady the ladder. Do not overreach — move it instead." |
| `potable_backflow` | "This connection to your drinking-water supply requires a backflow preventer. It is not optional and it is not expensive." |

Templates are versioned alongside prompts and reviewed as safety-critical content. Post-validation confirms that every flag the engine raised produced its template text verbatim in the output.

## 10.6 Presentation

The tutorial renders as a checkable, resumable list:

- Each phase collapses and expands; completed phases collapse automatically
- Each step has a checkbox that persists to the account (or to local storage when anonymous)
- Each step shows its parts and tools inline, so the user is not scrolling back to the BOM
- Estimated time is shown per phase and cumulatively
- Safety callouts render as visually distinct blocks that cannot be collapsed away
- The whole tutorial prints and exports to PDF with checkboxes intact
- Mobile layout is the primary design target — this is read one-handed, in a garage, with dirty hands

### Progress and pauses

Because builds span days, the tutorial records where the user stopped and what they had completed. Returning shows: "You're on Phase 3 of 7, about 2 hours of work remaining."

## 10.7 The post-build guide

The tutorial does not end at commissioning. A final section covers the first four weeks, which is when most first systems fail:

| Week | Content |
|---|---|
| Week 1 | Daily pH and EC checks, topping up, watching for leaks, transplant shock |
| Week 2 | First nutrient adjustment, root inspection, algae prevention |
| Week 3 | Growth expectations against a benchmark, thinning, first pruning where applicable |
| Week 4 | Full solution change, cleaning procedure, planning the next planting |

Plus a troubleshooting table indexed by symptom, not by cause, because a user searches by what they can see:

| What you see | Likely cause | What to do |
|---|---|---|
| Yellowing lower leaves | Nitrogen deficiency, or overwatering at the root zone | Check EC; check aeration |
| Brown, slimy roots | Root rot from warm or under-oxygenated solution | Check solution temperature and air pump; replace solution |
| White crust on media | Salt build-up | Flush with plain water |
| Green water | Algae from light reaching the solution | Block light at the reservoir and lid |
| Wilting despite a full reservoir | Pump failure or blockage | Check the pump and emitters immediately |
| Slow growth, pale leaves overall | Insufficient light | Compare actual photoperiod and fixture height against the plan |

This table is catalog data, filtered to the user's system and crops — not generated per plan.
